# 投后数据批量导入规范

> 本文档是**投后管理平台批量导入功能**的唯一权威规范。任何 AI（或人工）在生成投后项目 Excel 表格时，必须严格遵循本文档，否则生成的文件将无法被系统正确识别，导致导入失败或数据错乱。
>
> 对应代码：
> - 解析入口：`src/utils/importTemplate.js`
> - 落库处理：`src/data/store.js` 中的 `addProjects`
> - 上传页面：`src/pages/ImportPage.jsx`

---

## 1. 系统数据流总览

```
Excel 文件（.xlsx）
   │
   ├─ 每个 Sheet = 一个项目，Sheet 名 = 项目名称
   │
   ▼
parseExcelFile()  →  逐 Sheet 读取二维数组
   ▼
parseProjectSheet()  →  按「字段名」精确匹配，解析出 project 对象
   ▼
validateData()  →  校验必填项、数值范围
   ▼
addProjects()  →  写入本地状态 + 同步云端 PostgreSQL
```

**核心原则：字段名是精确匹配的**。系统通过「第一列的单元格文本」来判断这一行是什么内容，所以字段名（含括号、百分号）必须与本文档列出的**完全一致**，一个字符都不能差。

## 2. 文件结构要求

### 2.1 Sheet 规则

| 规则 | 说明 |
|---|---|
| 一个 Sheet = 一个项目 | Sheet 名称即为项目名称 |
| `使用说明` Sheet | 会被系统自动跳过，不参与解析 |
| Sheet 数量 | 至少 1 个（除「使用说明」外） |

### 2.2 行结构

每一行只有**前两列（A、B 列）**参与解析：

- **A 列**：字段名 / 表头 / 股东名称 / 期间
- **B 列**：字段值 / 持股比例（数值）

C 列及之后仅在「财务数据」模块中作为数据列使用（见 §5）。

### 2.3 模块标题行（可选）

`=== xxx ===` 形式的模块标题行是**装饰性的**，系统解析时仅将其作为「切换标志」，用于重置当前所处模块。**保留或删除均不影响解析结果**，但建议保留以方便人工阅读。

示例：
```
=== 基本信息 ===
=== 股权结构 ===
=== 财务数据 ===
=== 投资条款 ===
=== 投后情况 ===
```

## 3. 完整字段映射表

### 3.1 基本信息（basicMap）

| 模板字段名（A 列，精确） | 对应内部字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `项目名称` | name | 文本 | 是 | 为空时回退为 Sheet 名 |
| `所属行业` | industry | 文本 | 否 | 为空时默认「其他」 |
| `投资日期` | investmentDate | 文本 | 是 | 格式 `YYYY-MM-DD`，如 `2024-01-15` |
| `投资金额(万元)` | investmentAmount | 数字 | 否 | 单位：万元。留空=0 |
| `持股比例(%)` | shares | 数字 | 是 | 范围 0-100，我方持股占比 |
| `投资方式` | investType | 文本 | 否 | 为空默认「股权」 |
| `投后估值(万元)` | valuation | 数字 | 否 | 单位：万元。留空=0 |
| `项目简介` | description | 文本 | 否 | |
| `团队规模` | teamSize | 文本 | 否 | 如「50人」 |
| `联系人` | contactPerson | 文本 | 否 | |
| `联系电话` | contactPhone | 文本 | 否 | |
| `项目状态` | status | 文本 | 否 | 枚举：`normal` / `warning` / `danger`，默认 `normal` |

> **注意**：`项目状态` 填写英文枚举值，不要填中文。`normal`=正常，`warning`=关注，`danger`=预警。

### 3.2 投资条款（clauseMap）

| 模板字段名（A 列，精确） | 对应内部字段 |
|---|---|
| `回购条款` | repurchase |
| `优先清算权` | liquidation |
| `反稀释条款` | antiDilution |
| `随售权` | tagAlong |
| `拖售权` | dragAlong |
| `一票否决权` | veto |

全部为**文本**，可选。留空即可。

### 3.3 投后情况（postMap）

| 模板字段名（A 列，精确） | 对应内部字段 | 说明 |
|---|---|---|
| `投后联系人` | contactPerson | 会覆盖基本信息里的「联系人」 |
| `投后联系电话` | contactPhone | 会覆盖基本信息里的「联系电话」 |
| `最近沟通日期` | lastContactDate | 生成时间轴事件的日期，支持 `YYYY-MM-DD` 或中文「YYYY年M月D日」 |
| `项目亮点` | highlights | 合并进时间轴事件描述 |
| `风险提示` | risks | 合并进时间轴事件描述 |
| `后续计划` | nextSteps | 合并进时间轴事件描述 |
| `备注` | notes | 合并进时间轴事件描述 |

> 投后情况模块会整体转换成一条「投后沟通记录」时间轴事件。若 `最近沟通日期` 留空，则不生成该事件。
>
> `最近沟通日期` 支持标准格式 `2024-06-01`，也支持中文格式 `2024年6月1日`（或 `2024年6月`，缺省日按 1 号处理）。日期后跟的括号备注（如 `2026年8月4日（股东会）`）会被提取为「沟通事项」写入事件描述，日期本身统一标准化为 `YYYY-MM-DD` 用于排序与展示。

## 4. 股权结构解析规则

股权结构有两种写法，二选一即可：

### 4.1 带表头写法（推荐）

先出现表头行 `股东名称`（A 列），随后每一行是「股东名 + 持股比例」：

```
股东名称        持股比例(%)
我方基金        10
其他股东        90
```

- 表头行第一列必须精确为 `股东名称`，第二列可为 `持股比例(%)` 或留空
- 数据行：A 列=股东名称，B 列=持股比例（数字，0-100）

### 4.2 扁平写法（无表头）

无需 `股东名称` 表头，只要某行**第一列不是已知字段名、第二列是数字**，就会被识别为股权结构：

```
XXX基金    10
YYY投资    20
```

> 风险提示：扁平写法容易被误判。例如「团队规模 | 50人」这类行，如果 B 列是纯数字文本，可能被误识别为股东。**强烈建议使用带表头的写法**。

### 4.3 落库处理

- 若模板提供了股东明细，直接采用
- 若股东比例之和 < 99%，系统自动补一个「其他股东」补足 100%
- 若模板未提供任何股东明细，系统回退为 `我方基金 100%`

## 5. 董监高信息解析规则

### 5.1 字段结构

董监高信息是**一个板块**，位于股权结构之后、财务数据之前。字段分两类：

| 职务 | 模板字段名（A 列，精确） | 内部字段 | 人数 |
|---|---|---|---|
| 总经理 | `总经理` | directors.generalManager | 1 人 |
| 董事长 | `董事长` | directors.chairman | 1 人 |
| 监事 | `监事` | directors.supervisors[] | 多人 |
| 董事 | `董事`（或 `董事会成员`） | directors.boardMembers[] | 多人 |

### 5.2 填写规则

- **总经理 / 董事长**：各填一行，字段名精确匹配，值为姓名文本
- **监事**：填多行 `监事`（A 列重复写 `监事`），每行一人；也支持一行写多人并用顿号/逗号/分号分隔
- **董事会成员**：填多行 `董事`（A 列重复写 `董事`），每行一人；也支持一行写多人并用顿号/逗号/分号分隔

### 5.3 标准示例

```
=== 董监高信息 ===
总经理        张三
董事长        李四
监事        王五
监事        赵六
董事        钱七
董事        孙八
董事        周九
```

等价写法（监事、董事各一行多值）：

```
=== 董监高信息 ===
总经理        张三
董事长        李四
监事        王五、赵六
董事        钱七、孙八、周九
```

### 5.4 落库处理

- 董监高信息存为 `projects.directors`（jsonb），结构：`{ generalManager, chairman, supervisors: [], boardMembers: [] }`
- 总经理 / 董事长留空则存空字符串；监事 / 董事会成员无则存空数组

## 6. 财务数据解析规则

### 6.1 表头行

财务模块的表头行第一列必须精确为 `年份` 或 `期间`，从这一行开始进入财务模式，后续每行按表头列解析。

### 6.2 列名关键字匹配

财务表头**按关键字模糊匹配**（`包含`即命中），列顺序无关。匹配优先级如下：

| 表头关键字 | 内部字段 | 单位 | 匹配顺序 |
|---|---|---|---|
| 含 `营收` | revenue | 万元 | 1 |
| 含 `净利润` | netProfit | 万元 | 2 |
| 含 `毛利率` | grossMarginPct | % | 3 |
| 含 `毛利` | grossProfit | 万元 | 4 |
| 含 `资产负债率` | debtRatioPct | % | 5 |
| 含 `现金流` | operatingCashFlow | 万元 | 6 |

> **关键**：`毛利率` 必须排在 `毛利` 之前匹配，因此表头写作「毛利率(%)」会命中 grossMarginPct；写作「毛利(万元)」会命中 grossProfit。两者都可选。

### 6.3 期间列格式

财务数据行的**第一列（期间列）**支持两种格式：

| 格式 | 示例 | year | quarter |
|---|---|---|---|
| 纯年份 | `2022` | 2022 | 0 |
| 年份+季度 | `2026Q1`、`2026q3` | 2026 | 1 / 3 |

> 用正则 `^(\d{4})\s*[Qq](\d)` 拆分，`Q` 可大写可小写。

### 6.4 数值换算

| 字段 | 模板填写 | 入库存储 |
|---|---|---|
| 营收 / 净利润 / 现金流 / 毛利 | 万元（直接数值） | 原值 |
| 毛利率(%) | 0-100 百分比 | 仅用于反推毛利：`毛利 = 营收 × 毛利率 ÷ 100` |
| 资产负债率(%) | 0-100 百分比 | 自动 ÷100 转为 0-1 小数 |

> 资产负债率填 `45`（表示 45%），系统存成 `0.45`。若填 `0.45`（≤1），系统原样保留。

### 6.5 标准财务表头示例

```
年份      营收(万元)    净利润(万元)    毛利(万元)    资产负债率(%)    经营现金流(万元)
2023      1000         100           300          45              80
2024      1200         150           360          40              100
```

### 6.6 空数据行自动跳过

若某行只有期间（年份）而**所有财务数值列均为空**，该行会被自动跳过，不会生成「营收=0、净利润=0」的假数据点。因此模板中允许保留只有年份、暂未填数据的占位行，不会污染财务看板。

## 7. 数据校验规则（validateData）

导入前会逐项目校验，不通过则该项目报错，其余项目照常导入：

| 校验项 | 规则 | 报错提示 |
|---|---|---|
| 项目名称 | 非空，且 ≠「使用说明」 | 项目名称不能为空 |
| 投资日期 | 非空 | 缺少投资日期 |
| 持股比例 | 非空（0 视为已填写） | 缺少持股比例 |
| 持股比例 | 0 ≤ x ≤ 100 | 持股比例应在0-100之间 |
| 投资金额 | ≥ 0 | 投资金额不能为负数 |

## 8. 同名项目覆盖逻辑

系统以「项目名称」为唯一键：

- **同名项目已存在** → 覆盖更新，复用原 id，不产生重复
- **新项目** → 新建，并标记 `imported: true`

> 因此，修正已导入项目的错误时，直接重新上传同名 Sheet 即可覆盖，无需先删除旧数据。

## 10. 生成表格时必须遵守的要点（AI 自查清单）

1. **字段名精确匹配**：括号用半角 `()`，百分号用半角 `%`。例如 `投资金额(万元)`、`持股比例(%)`、`资产负债率(%)`。
2. **Sheet 名 = 项目名**，不要用「使用说明」作为项目 Sheet 名。
3. **必填三件套**：`项目名称`、`投资日期`、`持股比例(%)` 必须有值，否则该项目会被拦截。
4. **日期格式**：`投资日期` 用 `YYYY-MM-DD`（如 `2024-01-15`）；`最近沟通日期` 支持 `YYYY-MM-DD` 或中文 `2024年6月1日`，日期后的括号备注会自动提取为「沟通事项」。
5. **金额单位**：一律「万元」，不要带「万」字或逗号，直接填数字。
6. **持股比例**：填 0-100 的数字。
7. **资产负债率**：填 0-100 的数字（如 45 表示 45%），系统自动转小数。
8. **财务表头**：第一列写 `年份` 或 `期间`，其余列按 §6.2 关键字命名。
9. **财务期间值**：`2022` 或 `2026Q1` 格式。
10. **项目状态**：填英文 `normal` / `warning` / `danger`。
11. **股权结构**：用「股东名称」表头写法最稳妥，避免扁平写法误判。
12. **董监高信息**：`总经理`/`董事长` 各一人；`监事`/`董事` 可多人（每行一人，或一行多人用顿号/逗号/分号分隔）。

## 12. 已知限制与注意事项

1. **「轮次」字段不解析**：数据库 `projects.round`（融资轮次，如 A 轮/B 轮）在导入模板中**没有对应字段名**。如需填写轮次，需人工在系统内编辑补充，或后续扩展模板。
2. **同名覆盖不会清空财务**：覆盖同名项目时，若模板未提供财务数据，原财务数据保留。
3. **投后情况转时间轴**：投后情况模块不会单独存字段，而是合并成一条时间轴「投后沟通记录」事件。
4. **财务数据按期间倒序**：系统自动按 period 字符串倒序排序，无顺序要求，但建议按年份从旧到新填写，便于人工核对。
